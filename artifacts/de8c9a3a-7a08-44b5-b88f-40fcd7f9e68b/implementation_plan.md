# Data Management Refactor Plan

## Goal
Transition from runtime JSON ingestion to using a pre-built SQLite database shipped as an asset. This improves startup time, simplifies maintenance, and enables advanced features (Thesaurus).

## User Review Required
> [!IMPORTANT]
> This is a structural change. The `DataIngester` class will be obsolete and removed.
> The database will now be generated by a developer tool (`tool/build_db.dart`) and shipped in `assets/dictionary.db`.

## Proposed Changes

### 1. Directory Structure
- [MOVE] `assets/data/*.json` -> `dictionary/data/*.json`
- [MOVE] `assets/other/en_thesaurus.jsonl` -> `dictionary/other/en_thesaurus.jsonl`
- [NEW] `tool/` directory for the builder script.

### 2. Dependencies
- **dev_dependencies**: Add `sqlite3` (for the standalone build script).
- **dependencies**: Keep `sqflite` (for the Flutter app).

### 3. Developer Tool (`tool/build_db.dart`)
A standalone Dart script to:
1.  **Init DB**: Create `dictionary.db` using `sqlite3` (native).
2.  **Schema**:
    - `categories` (id, tag) - *Existing*
    - `words` (id, text, is_common) - *Existing*
    - `word_categories` (word_id, category_id) - *Existing*
    - `meanings` (id, word, pos, definitions, synonyms) - *[NEW]*
3.  **Ingest Data**:
    - Parse `dictionary/data/*.json` (Existing logic adapted).
    - Parse `dictionary/other/en_thesaurus.jsonl` (New logic).
4.  **Output**: Save to `assets/dictionary.db`.

### 4. Flutter App Logic
#### `lib/data/database_helper.dart`
- Modify `init()` to:
  - Check if `dictionary.db` exists in app documents.
  - If NOT, copy it from `rootBundle` (assets).
  - Open the database.

#### `lib/data/data_ingester.dart`
- [DELETE] Remove class. Logic moved to `tool/build_db.dart`.

#### `lib/main.dart`
- Remove `DataIngester` calls.
